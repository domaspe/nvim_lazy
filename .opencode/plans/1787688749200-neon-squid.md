# Plan: live tmux `@theme` → onedark variant switching

## Goal

Currently `lua/plugins/colorscheme.lua` reads tmux `@theme` once at startup and sets
`vim.o.background`. Make it re-check the variable and switch the onedark light/dark
variant without restarting nvim.

## Findings (how it can work)

- onedark's `colorscheme()` (init.lua:16-28) re-reads `vim.o.background` on every
  `:colorscheme onedark` — so `vim.o.background = "light"/"dark"` + reload is enough
  to switch variants live.
- **Gotcha**: onedark "sticks" to light. Once background=light has forced
  `style = "light"` (init.lua:21-22), reverting background to dark hits the
  `elseif style == "light"` branch (init.lua:23) and stays light. Fix: reset
  `require("onedark").set_options("style", "darker")` before each reload so dark
  resolves back to the configured "darker" style.

## Change (single file: `lua/plugins/colorscheme.lua`)

- Keep `tmux_background()`.
- Add `apply_tmux_theme()`:
  - read tmux var, compute target `bg`,
  - if `vim.o.background ~= bg`: reset style to `"darker"`, set `vim.o.background`,
    `vim.cmd("colorscheme onedark")`.
- In onedark's `init` (already runs at startup, before onedark loads), after the
  existing background init, register an autocmd group that calls `apply_tmux_theme()`.

Trigger (confirmed): `FocusGained` + `VimResume` autocmds — fires on tmux window/session
switch, no background timer.

## Verification

- In tmux: `tmux set -g @theme light` then switch away from and back to the nvim pane
  (or re-focus) → onedark goes light.
- `tmux set -g @theme dark`, refocus → goes back to "darker" (confirms the style-reset
  fix; without it, it would wrongly stay light).
- Toggle both ways a couple times to confirm no stickiness.
